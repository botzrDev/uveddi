# Uveddi v1.0.0 Release Plan

**Target Version**: 1.0.0 (first stable release)
**Baseline**: v0.0.3 (current state of this branch)
**Date**: 2026-08-09
**Release Type**: MAJOR — first stable public release of the CLI-focused product

---

## 1. Scope and Positioning

v1.0.0 promotes the current CLI-focused product from alpha to stable. It is a
stabilization release, not a feature release: the deliverable is the v0.0.3
codebase, verified, documented accurately, and versioned as 1.0.0.

### What v1.0.0 IS

- A stable, single-binary **CLI** for architectural and code-quality analysis
- **Commands**: `analyze`, `init`, `config`, `doctor`, `ci`, `hooks`, `migrate`,
  `license`, `help`, and (feature-gated) `plugin`
- **Languages** (default `cli-standard` build): Rust, Python, JavaScript,
  TypeScript via Tree-sitter; additional languages available behind
  per-language feature flags and license tiers
- **Detectors**: core anti-pattern detectors (god object, large class, dead
  code, code duplication, tight coupling, magic values, and related smells)
  plus security scanning with SARIF export — all available on the **free tier**;
  advanced cyclic-dependency detection is Pro-tier
- **Licensing**: tiered gating (Free / Pro / Team / Enterprise) with the
  `license` command for activation and status
- **Output**: Markdown, JSON, HTML reports; SARIF for CI security pipelines
- **Storage**: persistent SQLite database with `migrate` support
- **Plugins (opt-in)**: WASM component-model plugin host behind the
  `wasm-plugins` feature — shipped as experimental in v1.0.0
- **AI insights (opt-in)**: local Ollama integration behind the `cli-ai`
  feature — shipped as experimental in v1.0.0

### What v1.0.0 is NOT (explicitly out of scope)

These appear in older planning documents (written for the pre-CLI-refocus
architecture) and are **not** part of this release:

- Web dashboard / React frontend (removed in the CLI refocus)
- REST API server, WebSocket support, GraphQL (removed)
- TUI interface (removed as standalone; not a v1 surface)
- Prometheus metrics / enterprise monitoring (removed)
- Enterprise auth / RBAC / SSO (planned post-1.0)
- PostgreSQL backend (storage is SQLite)

The older documents `docs/release-planning/v1.0-issues.md`,
`docs/release-notes/v1.0-alpha-status.md`, and `docs/feature-status-matrix.md`
describe that earlier architecture and are retained for history only.

## 2. Release Gates

| Gate | Requirement | Result |
|------|-------------|--------|
| G1: Compile | `cargo check` clean on default features | see §5 |
| G2: Lint | `cargo clippy` no errors; `cargo fmt --check` clean | see §5 |
| G3: Tests | `cargo test` pass rate recorded; failures triaged and documented | see §5 |
| G4: Release build | `cargo build --release` succeeds; `uveddi -V` reports 1.0.0 | see §5 |
| G5: Smoke test | `uveddi analyze` on a sample tree produces a report | see §5 |
| G6: Docs | CHANGELOG 1.0.0 entry, README updated, release notes rewritten to match the shipped product | this PR |

## 3. Release Steps (this branch)

1. Verify gates G1–G5 on the branch.
2. Bump `Cargo.toml` version `0.0.3` → `1.0.0` (and `Cargo.lock`).
3. Add `[1.0.0]` entry to `CHANGELOG.md`.
4. Update `README.md` version/status (Alpha → Stable).
5. Rewrite `docs/RELEASE_NOTES_v1.0.md` to describe the actual shipped
   CLI product (the previous version described the removed web-dashboard
   architecture).
6. Commit and push to the release branch.

## 4. Post-merge Steps (maintainer actions)

These happen **after** this branch is reviewed and merged, so the tag points
at a commit on the default branch:

1. `git tag -a v1.0.0 -m "Version 1.0.0 - First Stable Release"` on the merge
   commit, then `git push origin v1.0.0`.
2. The tag push triggers `.github/workflows/release.yml`, which builds
   binaries for Linux (gnu/musl, x86_64/aarch64), macOS (x86_64/aarch64), and
   Windows (x86_64) with `--features full` and publishes a GitHub release.
3. Verify the published artifacts install and run (`uveddi -V` → `1.0.0`).
4. Announce per the usual channels once artifacts are verified.

## 6. Known Limitations Shipping in v1.0.0

- **WASM plugins** are experimental: the host and loader work, the plugin
  ecosystem is minimal (template + example plugins).
- **AI insights** require a locally running Ollama instance; output quality
  depends on the local model.
- **TypeScript** analysis handles common constructs; very complex type-level
  code may parse partially.
- License activation is offline/local; no license server round-trip.

## 7. Post-1.0 Roadmap (indicative)

- 1.0.x: bug-fix patches from early stable feedback
- 1.1: plugin ecosystem growth (registry, more first-party plugins),
  detector calibration improvements
- 1.2+: additional language tiers, IDE integrations, richer CI templates
