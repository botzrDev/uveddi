# Privacy Policy

**Effective Date:** October 9, 2025
**Last Updated:** October 9, 2025

This Privacy Policy describes how Uveddi ("we," "us," or "our") handles data when you use the Uveddi CLI architectural analysis tool (the "Software").

---

## 1. Overview

Uveddi is designed with privacy as a core principle. The Software performs **local analysis only** and does not transmit your source code, analysis results, or any personally identifiable information to our servers by default.

---

## 2. Data Collection and Processing

### 2.1 Local Analysis

All code analysis operations are performed **entirely on your local machine**. Uveddi:

- Reads source code files from directories you explicitly specify
- Performs static analysis and generates reports locally
- Stores analysis results in a local SQLite database (`.uveddi/cache.db`)
- Creates output files in directories you specify
- **Does not** upload your source code to any external server
- **Does not** send analysis results to any external service

### 2.2 No Telemetry by Default

Uveddi **does not collect or transmit telemetry data** by default. We do not track:

- Usage statistics
- Feature adoption metrics
- Error reports
- Performance data
- IP addresses
- System information

There is no built-in telemetry, analytics, or "phone home" functionality in the Software.

### 2.3 Optional AI Integration

If you explicitly enable the optional AI integration feature (`--enable-ai` flag), Uveddi may communicate with:

- **Your local Ollama instance**: When configured, Uveddi sends code snippets and analysis context to a locally-running Ollama service that you control. This communication occurs entirely on your local network.
  - **Data sent**: Code snippets, anti-pattern descriptions, and analysis context
  - **Data received**: AI-generated suggestions and remediation guidance
  - **Your control**: You control the Ollama installation, model selection, and network configuration

**Important**: If you configure Ollama to use remote or cloud-based inference services, your data may leave your local environment according to those services' privacy policies. We recommend reviewing the privacy policies of any AI services you integrate with Uveddi.

### 2.4 Export Formats

Uveddi generates reports in various formats (Markdown, JSON, HTML, SARIF) that are saved to your local filesystem. You are responsible for:

- Securing these output files
- Controlling who has access to analysis results
- Determining whether to commit reports to version control
- Managing distribution of reports within your organization

---

## 3. Data Storage

### 3.1 Local Cache Database

Uveddi maintains a local SQLite database at `.uveddi/cache.db` within analyzed project directories to enable:

- Incremental analysis (only re-analyzing changed files)
- Performance optimization
- Historical tracking of analysis results

**Data stored**:
- File paths and modification timestamps
- Analysis results and anti-pattern detections
- Configuration settings
- Detector execution metadata

**Data retention**: Cache data persists indefinitely until you manually delete the `.uveddi` directory. You can clear the cache at any time with `uveddi clean`.

**Security**: The cache database is stored locally and is not encrypted. Ensure appropriate filesystem permissions are configured to protect sensitive analysis data.

### 3.2 Configuration Files

Uveddi may create local configuration files:
- `.uveddi.toml`: Project-specific settings
- `~/.uveddi/config.toml`: Global user settings (if implemented)

These files contain only configuration preferences and do not include source code or analysis results.

---

## 4. Third-Party Services

### 4.1 Ollama (Optional)

When AI integration is enabled, Uveddi communicates with Ollama, a third-party LLM runtime:

- **Communication**: HTTP API calls to your specified Ollama endpoint (default: `http://localhost:11434`)
- **Data shared**: Code snippets and analysis context as prompt text
- **Privacy responsibility**: You are responsible for your Ollama configuration and any downstream services Ollama uses
- **Opt-out**: Do not use the `--enable-ai` flag to avoid any AI integration

See Ollama's privacy policy at https://ollama.ai/ for more information.

### 4.2 No Other External Services

Uveddi does not integrate with or communicate with any other external services, APIs, or cloud platforms.

---

## 5. Support and Debugging

### 5.1 Support Requests

If you contact our support team (support@uveddi.com), you may choose to share:

- Log files generated by Uveddi
- Configuration files
- Anonymized code snippets to reproduce issues
- System information relevant to troubleshooting

**Your choice**: You are never required to share source code or analysis results. We will work with you to diagnose issues using minimal information.

**Data retention**: Support communications are retained for up to 2 years for customer service purposes. You may request deletion of your support data at any time by contacting privacy@uveddi.com.

### 5.2 Diagnostic Logging

Uveddi generates log files to assist with debugging:

- **Location**: Configurable via `--log-file` flag or logs to stderr by default
- **Contents**: Operation traces, performance metrics, error messages
- **Sensitive data**: Logs may include file paths but do not contain source code contents
- **Your control**: You control log generation, storage location, and retention

**Recommendation**: Review log files before sharing them to ensure they do not contain sensitive paths or information.
