  Uveddi is a code analysis tool written in Rust that follows a layered architecture. Here's how data flows through

  Entry Point:

  When you run uveddi analyze ./src, here's what happens in src/main.rs:62:

  #[tokio::main]
  async fn main() -> Result<()> {
      // Initialize logging and error handling
      color_eyre::install()?;
      uveddi::core::logging::unified::init_logging_with_config(&log_level, log_format == "json")?;

      // This calls the main application logic
      uveddi::application::run_app().await
  }

  The #[tokio::main] attribute is Rust's way of creating an async runtime. Think of it like setting up a JavaScript
  event loop - it allows the program to handle multiple tasks concurrently without blocking.

  CLI Command Parsing:

  In src/application/mod.rs, the run_app() function uses Clap (Command Line Argument Parser) to understand what
  command you typed:

  #[derive(Parser)]
  struct Cli {
      #[command(subcommand)]
      command: Commands,
  }

  #[derive(clap::Subcommand)]
  enum Commands {
      Analyze(AnalyzeCommand),    // This handles "uveddi analyze"
      Config(ConfigCommand),      // This handles "uveddi config"
      Doctor(DoctorCommand),      // This handles "uveddi doctor"
      // ... more commands
  }

  In Rust, an enum is like a union type - it can be one of several variants. The #[derive(Parser)] tells Clap to
  automatically generate command parsing code.

● Step 2: AST Parsing - How Code Becomes Data

  Here's how Uveddi transforms your source code into analyzable data structures:

  The Key Data Structures:

  1. ParsedFile - The main result of parsing a file:
  pub struct ParsedFile {
      pub file_path: Arc<PathBuf>,    // Path to the source file
      pub language: SourceLanguage,   // Rust, Python, JavaScript, etc.
      pub tree: Option<Tree>,         // Tree-sitter AST tree
      pub source: Arc<String>,        // The actual source code text
      pub custom_ast: Arc<Option<CustomAst>>, // Uveddi's simplified AST
  }

  2. SourceLanguage - Supported languages:
  enum SourceLanguage {
      Rust,       // .rs files
      Python,     // .py files  
      JavaScript, // .js, .jsx files
      TypeScript, // .ts, .tsx files
  }

  The Parsing Process:

  When you run uveddi analyze ./src, here's what happens:

  1. File Discovery: Uveddi scans the directory for supported files
  2. Language Detection: Uses file extension (src/ast/tree_sitter_impl.rs:detect_language)
  3. Security Validation: Checks file size and type
  4. Cache Check: Looks for cached AST based on file modification time
  5. Parse or Retrieve: Either parses fresh or returns cached result

  The Smart Caching System:

  Uveddi uses an LRU (Least Recently Used) cache to avoid re-parsing unchanged files:

  // In src/ast/tree_sitter_impl.rs:parse_file
  let cache_result = {
      let mut cache = self.cache.lock()?;
      if let Some(cached) = cache.get(&path_str) {
          if cached.modified_at == file_modified_time {
              // File hasn't changed - use cached AST
              return cached.clone();
          } else {
              // File changed - remove stale cache
              cache.pop(&path_str);
          }
      }
  };

  Key Rust Concepts Here:

  - Arc<String>: Atomic Reference Counted smart pointer - allows multiple threads to safely share the same string data
  - Mutex<LruCache>: Thread-safe cache that can be accessed from multiple threads
  - Option<Tree>: Rust's way of saying "this might exist or might be None" (like nullable in other languages)

  Real Example:

  When you parse main.rs, you get:

  - source: The actual text content of main.rs
