Uveddi Documentation

Entity-Relationship Diagram (ERD) for Uveddi

This ERD outlines the core entities and their relationships for the Uveddi product, focusing on the data model required for its architectural analysis, reporting, user management, and plugin system.

Entities:

  • User: Represents a Uveddi user.
  • Organization: Represents a company or team using Uveddi.
  • Project: Represents a software codebase being analyzed.
  • AnalysisRun: Represents a single execution of the Uveddi analysis.
  • ArchitecturalIssue: Represents a detected architectural anti-pattern or issue.
  • CodeSnippet: Represents a specific segment of code related to an ArchitecturalIssue.
  • AntiPatternType: A catalog of predefined architectural anti-patterns the tool can detect.
  • Plugin: Represents a custom scanner or extension for Uveddi.
  • Report: Represents the generated markdown report for an AnalysisRun.
  • Diagram: Represents a visual diagram embedded within a Report.

-----Entity Attributes:

User

  • user_id (Primary Key)
  • email (Unique, Required)
  • username (Unique, Required)
  • password_hash (Required)
  • created_at
  • last_login
  • role (e.g., 'individual', 'org_admin', 'org_member')
  • organization_id (Foreign Key to Organization, Nullable for individual users)

Organization

  • organization_id (Primary Key)
  • name (Unique, Required)
  • subscription_tier (e.g., 'free', 'paid_api')
  • created_at
  • api_key_usage_limit (for paid tiers)

Project

  • project_id (Primary Key)
  • organization_id (Foreign Key to Organization, Required)
  • name (Required)
  • repository_url (Required)
  • last_analyzed_commit
  • config_data (JSONB/Text, stores .archlintignore rules, analysis scopes, etc.)
  • created_at

AnalysisRun

  • run_id (Primary Key)
  • project_id (Foreign Key to Project, Required)
  • user_id (Foreign Key to User, Nullable if run by CI/CD)
  • start_time (Required)
  • end_time
  • status (e.g., 'running', 'completed', 'failed', 'cancelled')
  • ai_model_used (e.g., 'local_mistral', 'openai_gpt4', 'anthropic_claude3')
  • total_files_scanned
  • total_issues_found
  • exit_code (for CI/CD integration)
  • raw_analysis_output (Text/JSONB, for debugging/advanced usage)

ArchitecturalIssue

  • issue_id (Primary Key)
  • run_id (Foreign Key to AnalysisRun, Required)
  • anti_pattern_type_id (Foreign Key to AntiPatternType, Required)
  • file_path (Required)
  • line_start
  • line_end
  • severity (e.g., 'critical', 'high', 'medium', 'low')
  • title (Generated by AI/Template, Required)
  • description (Generated by AI/Template, Required)
  • ai_refactoring_suggestion (Text, Generated by AI)
  • is_ignored (Boolean, default false, user can mark issues as ignored)
  • ignored_by_user_id (Foreign Key to User, Nullable)
  • ignored_at

CodeSnippet

  • snippet_id (Primary Key)
  • issue_id (Foreign Key to ArchitecturalIssue, Required)
  • content (Text, the actual code snippet)
  • language (e.g., 'rust', 'python', 'javascript')
  • context_lines_before
  • context_lines_after

AntiPatternType

  • anti_pattern_type_id (Primary Key)
  • name (Unique, e.g., 'Cyclic Dependency', 'God Object', 'Leaky Abstraction')
  • description
  • category (e.g., 'Dependency-Based', 'Abstraction-Based', 'Microservice-Specific')
  • detection_heuristic_notes (Text, for internal documentation)

Plugin

  • plugin_id (Primary Key)
  • name (Unique, Required)
  • version (Required)
  • description
  • author_user_id (Foreign Key to User, Nullable for official plugins)
  • github_repo_url (Optional)
  • is_official (Boolean, default false)
  • is_approved (Boolean, for security/quality checks)
  • created_at
  • last_updated

Report

  • report_id (Primary Key)
  • run_id (Foreign Key to AnalysisRun, Unique, Required)
  • file_path (Path where the markdown report is saved/stored)
  • content (Text, the full markdown report content)
  • generated_at

Diagram

  • diagram_id (Primary Key)
  • report_id (Foreign Key to Report, Required)
  • type (e.g., 'Mermaid.js', 'PlantUML', 'Graphviz')
  • syntax_content (Text, the diagram-as-code syntax)
  • description (Caption for the diagram)
  • associated_issue_id (Foreign Key to ArchitecturalIssue, Nullable, links diagram to specific issue if applicable)

-----Relationships:

  • User --- 0..N : 1 --- Organization
    • An Organization can have many Users.
    • A User can belong to one Organization (or none if individual).
    • (One-to-Many, organization_id in User)
  • Organization --- 1 : 0..N --- Project
    • An Organization can have many Projects.
    • A Project belongs to exactly one Organization.
    • (One-to-Many, organization_id in Project)
  • Project --- 1 : 0..N --- AnalysisRun
    • A Project can have many AnalysisRuns.
    • An AnalysisRun belongs to exactly one Project.
    • (One-to-Many, project_id in AnalysisRun)
  • User --- 0..1 : 0..N --- AnalysisRun
    • A User can initiate many AnalysisRuns.
    • An AnalysisRun may or may not be directly initiated by a specific User (e.g., CI/CD).
    • (One-to-Many, user_id in AnalysisRun)
  • AnalysisRun --- 1 : 0..N --- ArchitecturalIssue
    • An AnalysisRun can detect many ArchitecturalIssues.
    • An ArchitecturalIssue belongs to exactly one AnalysisRun.
    • (One-to-Many, run_id in ArchitecturalIssue)
  • ArchitecturalIssue --- 1 : 0..N --- CodeSnippet
    • An ArchitecturalIssue can be associated with many CodeSnippets (e.g., multiple lines, or contextual code).
    • A CodeSnippet belongs to exactly one ArchitecturalIssue.
    • (One-to-Many, issue_id in CodeSnippet)
  • AntiPatternType --- 1 : 0..N --- ArchitecturalIssue
    • An AntiPatternType can describe many ArchitecturalIssues.
    • An ArchitecturalIssue is of exactly one AntiPatternType.
    • (One-to-Many, anti_pattern_type_id in ArchitecturalIssue)
  • AnalysisRun --- 1 : 0..1 --- Report
    • An AnalysisRun generates exactly one Report.
    • A Report belongs to exactly one AnalysisRun.
    • (One-to-One, run_id in Report is also PK and FK)
  • Report --- 1 : 0..N --- Diagram
