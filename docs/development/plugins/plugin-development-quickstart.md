# Uveddi Plugin Development Quickstart

This guide will help you create your first Uveddi WASM plugin in minutes.

## Prerequisites

1. **Rust** (1.70+) - Install from [rustup.rs](https://rustup.rs/)
2. **wasm-pack** - Install with:
   ```bash
   curl https://rustwasm.github.io/wasm-pack/installer/init.sh -sSf | sh
   ```
3. **Optional**: `wasm-opt` for optimization:
   ```bash
   # macOS
   brew install binaryen
   
   # Ubuntu/Debian
   sudo apt-get install binaryen
   ```

## Quick Start

### 1. Generate a New Plugin

```bash
# Interactive generation
./scripts/generate-plugin.py

# Or with configuration file
./scripts/generate-plugin.py --config my-plugin-config.json
```

Example configuration:
```json
{
  "plugin_name": "my-security-plugin",
  "version": "1.0.0",
  "author": "Your Name",
  "description": "Custom security analysis plugin",
  "license": "MIT",
  "languages": ["rust", "python"],
  "detector_types": ["security", "quality"],
  "read_files": true,

  "network_access": false,

    "Checks for SQL injection patterns"

```

### 2. Implement Your Analysis Logic

Edit `src/lib.rs` to add your detection logic:

```rust
#[wasm_bindgen]
impl MySecurityPlugin {
    #[wasm_bindgen]
    pub fn analyze(&self, code: &str, language: &str, file_path: &str) -> Result<JsValue, JsValue> {
        let mut issues = Vec::new();

        // Example: Detect hardcoded passwords
        if let Some(line_num) = self.find_hardcoded_secrets(code) {
            issues.push(Issue {
                id: "SEC-001".to_string(),
                severity: "high".to_string(),
                message: "Potential hardcoded secret detected".to_string(),
                file: file_path.to_string(),
                line: line_num,
                column: 0,
                category: "security".to_string(),
                suggestion: Some("Use environment variables or a secure vault".to_string()),
            });
        }

        // Calculate metrics
        let metrics = Metrics {
            lines_of_code: code.lines().count(),
            complexity: self.calculate_complexity(code),
            maintainability_index: 100.0,
            custom_metrics: HashMap::new(),
        };

        let result = AnalysisResult { issues, metrics };
        JsValue::from_serde(&result)
            .map_err(|e| JsValue::from_str(&format!("Serialization error: {}", e)))
    }

    fn find_hardcoded_secrets(&self, code: &str) -> Option<usize> {
        // Simple pattern matching for demonstration
        let secret_patterns = [
            r"password\s*=\s*['\"][^'\"]+['\"]",
            r"api_key\s*=\s*['\"][^'\"]+['\"]",
            r"secret\s*=\s*['\"][^'\"]+['\"]",
        ];

        for (line_num, line) in code.lines().enumerate() {
            for pattern in &secret_patterns {
                if regex::Regex::new(pattern).unwrap().is_match(&line.to_lowercase()) {
                    return Some(line_num + 1);
                }
            }
        }
        None
    }
}
```

### 3. Build and Test

```bash
cd my-security-plugin

# Build the plugin
make build

# Run tests
make test

# Create package
make package
```

### 4. Test with Uveddi

```bash
# Install plugin locally
make install-plugin

# Test with Uveddi
uveddi analyze ./test-code --plugins my-security-plugin --verbose
```

### 1. Rule Engine Plugin

For custom organizational rules and policies:

```rust
// Example: Enforce naming conventions
pub fn check_naming_conventions(&self, ast: &AstNode) -> Vec<Issue> {
    let mut issues = Vec::new();
    
    // Find all function definitions
    for func_node in self.find_functions(ast) {
        let func_name = self.extract_name(&func_node);
        
        // Check snake_case convention
        if !func_name.chars().all(|c| c.is_lowercase() || c == '_') {
            issues.push(Issue {
                id: "NAMING-001".to_string(),
                severity: "medium".to_string(),
                message: format!("Function '{}' should use snake_case", func_name),
                // ... other fields
            });
        }
    }
    
    issues
}
```

### 3. Metrics and Visualization Plugin

For advanced code metrics:

```rust
// Example: Calculate advanced complexity metrics
pub fn calculate_cognitive_complexity(&self, ast: &AstNode) -> u32 {
    let mut complexity = 0;
    let mut nesting_level = 0;
    
    self.traverse_ast(ast, &mut |node, depth| {
        match node.node_type.as_str() {
            "if_statement" | "while_statement" | "for_statement" => {
                complexity += 1 + nesting_level;
                nesting_level += 1;
            }
            "match_expression" => {
                complexity += 1 + nesting_level;
                // Each match arm adds complexity
                complexity += self.count_match_arms(node);
            }
            _ => {}
        }
    });
    
    complexity
}
```

## Advanced Features

### Tree-sitter Integration

Use Tree-sitter for precise AST analysis:

```toml
# Cargo.toml
[dependencies]
tree-sitter = { version = "0.25", optional = true }
tree-sitter-rust = { version = "0.24", optional = true }

[features]
rust-support = ["tree-sitter", "tree-sitter-rust"]
```

```rust
use tree_sitter::{Parser, Language, Query, QueryCursor};

pub fn analyze_with_tree_sitter(&self, code: &str) -> Vec<Issue> {
    let language = tree_sitter_rust::language();
    let mut parser = Parser::new();
    parser.set_language(language).unwrap();
    
    let tree = parser.parse(code, None).unwrap();
    let root_node = tree.root_node();
    
    // Use Tree-sitter queries for pattern matching
    let query = Query::new(
        language,
        "(function_item name: (identifier) @func_name)"
    ).unwrap();
    
    let mut cursor = QueryCursor::new();
    let matches = cursor.matches(&query, root_node, code.as_bytes());
    
    // Process matches and generate issues...
    vec![]
}
```

```rust
pub struct PluginConfig {
```

### Performance Optimization

Optimize for large codebases:

```rust
use std::collections::HashMap;

pub struct AnalysisCache {
    file_hashes: HashMap<String, String>,
    results: HashMap<String, AnalysisResult>,
}

impl AnalysisCache {
    pub fn get_cached_result(&self, file_path: &str, content_hash: &str) -> Option<&AnalysisResult> {
        if let Some(cached_hash) = self.file_hashes.get(file_path) {
            if cached_hash == content_hash {
                return self.results.get(file_path);
            }
        }
        None
    }
    
    pub fn store_result(&mut self, file_path: String, content_hash: String, result: AnalysisResult) {
        self.file_hashes.insert(file_path.clone(), content_hash);
        self.results.insert(file_path, result);
    }
}
```

## Testing Your Plugin

Create comprehensive tests:

```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn test_hardcoded_secret_detection() {
        let plugin = MySecurityPlugin::new();
        let code = r#"
            fn main() {
                let password = "secret123";
                let api_key = "abc123def456";
            }
        "#;
        
        let result = plugin.analyze(code, "rust", "test.rs").unwrap();
        let analysis: AnalysisResult = result.into_serde().unwrap();
        
        assert_eq!(analysis.issues.len(), 2);
        assert_eq!(analysis.issues[0].id, "SEC-001");
    }

    #[test]
    fn test_no_false_positives() {
        let plugin = MySecurityPlugin::new();
        let code = r#"
            fn main() {
                let user_input = get_user_password();
                println!("Welcome!");
            }
        "#;
        
        let result = plugin.analyze(code, "rust", "test.rs").unwrap();
        let analysis: AnalysisResult = result.into_serde().unwrap();
        
        assert_eq!(analysis.issues.len(), 0);
    }
}
```

## Best Practices

### 1. Error Handling
- Always validate input parameters
- Provide meaningful error messages
- Handle malformed code gracefully

### 2. Performance
- Cache expensive computations
- Limit memory usage
- Respect timeout limits

### 3. Security
- Validate all external input
- Don't expose sensitive information
- Follow principle of least privilege

### 4. Testing
- Test with various code samples
- Include edge cases
- Test error conditions

### 5. Documentation
- Document all configuration options
- Provide usage examples
- Include troubleshooting guide

## Troubleshooting

### Common Issues

1. **WASM Build Fails**
   ```bash
   rustup target add wasm32-unknown-unknown
   ```

2. **Plugin Not Loading**
   - Check `plugin.toml` syntax
   - Verify WASM file is valid
   - Check Uveddi logs for errors

3. **Performance Issues**
   - Profile with `twiggy top plugin.wasm`
   - Enable optimization: `make optimize`
   - Consider caching strategies

4. **Memory Limits**
   - Monitor memory usage
   - Reduce memory allocations
   - Use streaming for large files
